# AmazMe Python 后端：本机优先建设方案

2026-10-24 用户确认。本文件取代此前以 Linux VM／容器为默认执行域的方案。
AmazMe 是主要操作用户本机环境的桌面 AI 助手。Python 继续负责业务；仅维护一个本机执行路径。

## 产品范围

保留会话、分支、压缩、队列、子任务、审批、取消、定时任务、模型和账号、工作区与文件、
Web/Electron/TUI/CLI/RPC/SDK、SSH 远端、MCP、插件、Codemode、computer-use、记忆、工作流、
搜索、项目、设置、产物、分享和新格式导入导出。各能力是否完成以运行证据为准。
不承担旧 TS 接口、旧生态、历史数据兼容；不删除真实用户数据、未知资源或其他会话修改。
版本从 0.1.0 开始，版本号、不可变 build_id、协议和存储格式分别校验。

## 执行与进程职责

客户端经 Host 提交；Host 持久投递；会话 worker 独占会话 SQLite，保存模型及工具意图、审批与结果；
独立 Python Supervisor 拥有执行进程。一个 Uvicorn worker，不复制同一 profile 管理状态。
本机 shell 在实际工作目录运行，使用本机工具链；文件服务直接访问已选本机工作区。
删除 Lima、Docker 通道、镜像准备/分发、容器/cgroup 证明和 guest 路径映射，不新增双后端或预留适配层。

保留以下有明确用途的机制：

| 机制 | 目的 |
| --- | --- |
| profile 锁、会话写锁 | 同一持久状态只有一个写入所有者 |
| host_epoch、worker_id、execution_epoch | 拒绝旧 Host 停止、旧 worker 放行和迟到结果；epoch 是授权代际 |
| build_id、参与者名册、更新冻结 | 避免不同构建混跑，更新前停止/核对受管参与者 |
| 稳定请求/调用 ID 和参数摘要 | 丢回执同 ID 查询或返回原结果；不同参数冲突；未知效果不自动重放。新建会话可由调用方给出编号，相同内容返回原行 |
| 启动预约与放行 | 先持久登记执行归属，再允许 shell 初始化和用户代码执行 |
| 受管进程生命周期记录 | 对直接子进程及观察到的后代执行取消、超时、退出回收与重启核对 |
| 有界输出、资源数量、重启预算 | 控制内存、磁盘和故障扩散；不宣称 OS 沙箱资源隔离 |

## 执行契约

调用结果、资源状态和副作用核对分别记录。资源状态为 running、stopping、exited 或 stop_unconfirmed；
调用结果为 pending、completed 或 unknown。cancel_requested 只表示取消意图。
退出记录限定为已登记/已观察的受管进程，不声称所有脱离后代已消失。

普通命令属于一次调用。稳定 scope 在持久登记后放行；监督器负责排空 stdout/stderr 并有界保存。
超时/取消先关闭准入，再停止该 scope 的已知进程，等真实退出；不能只因发出信号就报告已停止。
调用结果一旦持久化，清理失败不能把它改写成成功或重做。未放行的启动可以确定无用户副作用；
放行后失联/崩溃而无结果必须 unknown，同一调用 ID 不重新执行。

Host/worker 崩溃不等于其全部工具消失。监督器存活时继续负责执行；监督器重启先核对每个历史 scope。
固定受管进程可用继承锁证明其自身生命周期，不能把该证明扩大到任意子进程。
PID 必须结合出生身份和归属核对；身份不明不发信号，不按进程名扫描杀进程。
可追踪后代尽力终止；任意 setsid、双重 fork、主动脱离或 OS 权限限制不保证可追踪。
正常命令按观测到的真实退出结算，一般的平台限制不会把每个命令都变成永久 blocked。
具体未知结果阻止该调用自动重放，已知未退出的资源阻止相关冲突；不得依赖全 profile 的 VM 停止兜底。

长驻开发服务器、PTY 和 stdio MCP 是明确登记的会话资源，由 Supervisor 持有。
页面断线、一次回答结束及 worker 空闲回收不结束这些资源；显式关闭、停止后端与更新按资源归属停止。
监督器崩溃不能恢复的交互通道明确显示失联，不自动重启第三方命令。
远端连接保留独立认证/主机密钥和断连语义，不作为本机执行后端或启动前提。

## 安全、文件与凭据

本机 shell 具有当前用户的权限，能够访问该用户可访问的文件、网络和系统能力。
文件 API 的工作区/链接检查只约束该 API；命令审批只约束执行放行，二者都不是 OS 沙箱。
保留回环认证、私有 IPC、0700/0600 权限、客户端绑定、构建/代际校验、参数验证和必要审批。
模型、工作流等自动发起的命令须经执行策略；审批绑定完整命令、工作区、构建和 revision。
明确高风险操作需用户确认，不靠命令关键字声称能完整识别 shell 行为。

环境支持本机 PATH、HOME 和工具链；不自动把 Host 控制令牌、模型账号密钥或全部环境变量传给工具。
凭据由所属模块使用，日志与报告脱敏；Shell 可用用户身份读取文件这一事实必须如实说明。
不自动转发 SSH agent/全部密钥，不绕过 TCC、Developer ID、签名、公证和更新发布者校验。

文件按工作区身份和真实根路径定位，展示本机路径。读预览可截断，备份和恢复使用完整摘要与内容。
受检写入前持久保存检查点；摘要变化拒绝覆盖；恢复只作用于指定文件且再次核对当前摘要。
原始 shell 可以直接改文件，不承诺透明自动备份或撤销任意 shell/网络副作用。

## 持久化与客户端

复用 Host 元数据与会话 SQLite、串行事务队列、审批、任务和事件批次；不为本次执行调整重写业务内核。
损坏/缺失/不支持的存储格式先拒绝写入；新执行格式拒绝旧 VM 执行库，保留文件，不静默迁移或清空。
WebSocket 的 attachment、ACK、有界重放、快照重同步保留。客户端断线不取消已接纳工作。
原生执行契约通过 Pydantic 生成 OpenAPI/事件 schema/TS 声明，消费者同一阶段修改，禁止保留两套含义。

## 实施与验收

| 阶段 | 交付 | 运行验收 |
| --- | --- | --- |
| A 契约收敛 | 本方案、架构、状态/资源归属与验收台账一致 | 旧 VM 保证标为历史，现行契约不再要求 VM |
| B 本机首个闭环 | shell、文件、审批、检查点和一个客户端 | 无 VM 资源可启动；本机工具链；同 ID 去重、过期审批、取消/超时、崩溃恢复、检查点冲突/恢复 |
| C 长驻与全客户端 | PTY、MCP、开发服务和各客户端状态 | resize、断线重连、MCP 审批/取消、worker 回收不误杀服务；旧控制与未知结果不重放 |
| D 产品与交付 | 剩余能力、删除旧业务依赖、1.0.0 前的本机自用包 | 独立安装、真实供应商/TCC/SSH 场景、更新、性能和磁盘预算。签名、公证和更新发布者校验留到 1.0.0 且明确要求发布之后，不绕过系统安全 |

B 全面审查、修复、验证后原子提交，再继续 C。阶段中未就绪的接口明确返回不可用，不回退到 VM。
C 按会话 PTY、stdio MCP、其余客户端分别形成可验收提交。PTY 输入先登记稳定 ID 再发送，
重连查询同一终端；不确定输入不重放。协议窗口 32 KiB，重连记录最多 256 KiB。页面打开 `@xterm/xterm` 5.5.0 的 DOM 画面。键盘、光标应答和已打开的鼠标跟踪都走原来的输入编号。Electron、`amazme-backend tui`、print/JSON CLI、RPC、Python SDK 和默认交互画面已按各自范围验收。TUI 和默认交互画面在当前进程内沿用未确认输入。CLI 失败重试沿用代理目录里的编号。RPC 和 SDK 由调用方传入编号。Electron 页面丢回执后沿用同一输入编号。监督器冻结后不开始新的本机执行。各客户端没有重跑冻结和进程崩溃。输出游标按 UTF-16 码元计数。
stdio MCP 在会话本机工作目录启动，复用已验证的受管服务生命周期；不继承全部环境或凭据。
启动命令由用户明确提交，工具调用另行审批。持久保存原始 JSON 参数、调用 ID、审批摘要及结果；
支持工具目录的 inputSchema、分页与结构化结果。发出调用之后的超时/失联不能伪装成尚未执行。
MCP 取消通知是尽力请求；显式停止服务还须核对本机受管进程。服务关闭或监督器崩溃不自动重启。
采用已核对的 MCP stdio/工具协议子集，未实现的传输、OAuth 和媒体呈现单独列出，不能以 mock 服务替代真实兼容性证据。
C2 已分两段验收：先是用户连接服务、手动调用和审批，再是模型经会话意图、审批、稳定调用 ID、结果核对和取消使用 MCP。
手动调用通过不等于模型可用 MCP；模型单元通过也不等于动态目录、其他传输或任意第三方服务可用。
模型不能调用 Host 的用户审批接口代替用户决定。当前目录是连接时快照，并在模型调用前落盘；与已审批 schema 不一致时拒绝发送。
动态目录刷新和更多传输按实际需求另验收，不扩展为多执行后端。
测试按新契约改写：保留真实取消、双重崩溃、PID 身份不符、重复执行、越权与其他会话不受影响的风险验证。
setsid/双重 fork 用例验证诚实结果、不误杀、不重放，不再以任意后代全部消失为成功条件。
旧 P0/P1/P2 VM 报告仅是历史事实，不能证明本机执行完成。实际平台/真实模型证据与 faux/单测分别登记。

## 构建与操作约束

严禁重复构建和测试盘积累；不恢复已清理的 VM。源码验证先行，只在需要验证安装行为时构建。
本轮只保留一个当前安装目录，更新实验才允许明确的 A/B 两份；不为每个用例重复打包。
验证串行复用所属执行服务，退出核对自己创建的进程与临时目录；不得删除未知路径。
构建、运行器检查实际分配磁盘（稀疏文件不能用逻辑长度代替），记录高水位并设置占用/空闲空间阈值。
同一检查由 `backend/tools/resource_census.py` 执行。普查命令只报告；打包和运行器只删除自己目录里已确认没有进程引用的超限产物。
阈值检查是预算守卫，不冒充文件系统硬配额；超过阈值停止新增工作并清理确认归属的本轮临时产物。
不得执行发布、tag、推送、合并 main 或关闭整机；睡眠/断电证据不足保持未验收。

当前实施状态与新证据统一记录在 `python-backend-completion.md`。
