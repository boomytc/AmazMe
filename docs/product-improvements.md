# AmazMe 产品改进与验收

## 目标

在现有 Pi 库、Durable 宿主和 Web/TUI/桌面呈现上吸收 Pi、DeepSeek Harness、QwenPaw、Grok Build 的优秀能力。既有上游记录中的“暂缓”不是产品范围限制。能力必须连接实际执行、持久化、用户交互和失败恢复，不能只增加入口或占位界面。

参考源码位于同级目录 `pi`、`deepseek-harness`、`QwenPaw`。Grok Build 的开源树仅作历史参考，以[官方发布记录](https://x.ai/changelog/build)、[工作流说明](https://x.ai/news/workflows)和[记忆说明](https://x.ai/news/grok-build-memory)确认产品行为，无法确认的内部实现不当成事实。产品保持 `@amazme/*` 包名、中文与英文界面、现有设计令牌和从上到下的依赖方向。不移植整个参照产品，不增加旧 API 转接或双份权威状态。

## 每模块交付规则

1. 重新阅读实现与参照源码，先定义行为、状态归属和用户动作。
2. 修改包后先构建该包，再运行该包测试；不用根目录的全量 build/test 替代验证。
3. 默认不新增单元测试或集成测试，使用已有检查与实际入口验证功能。真实浏览器、独立安装、子进程与存储恢复使用实际入口。
4. 重读最终文件和 diff，核对要求、生命周期、失败路径、国际化、依赖、重复状态及产物。
5. 自审查有问题就修正；通过后只提交本模块文件，提交说明用中文说明原因。不推送。

## 最终完成条件

所有模块都有当前源码、构建、测试与实际运行证据。UI 必须检查真实呈现及操作，性能必须有测量，外部模型验证和确定性本地协议验证分开报告。清除临时 TODO 卡片、空测试占位与本任务启动的服务，确认 git 工作区状态。证据不足时保持目标进行中，不用“生产就绪”代替缺失的验证。

### 文件条件写入后端

- 执行环境提供打开文件的版本标记及条件发布，版本包含文件身份、大小、修改与变化元数据。新建采用不覆盖已有条目的发布方式；替换暂存完整内容，在发布前再次核对版本和路径目标。写入意图在异步等待前复制。
- Node 同一进程的条件写入共享路径屏障，取消排队调用仍保留前序屏障。远程 daemon 分块暂存并串行核对和发布；取消、关闭句柄及正常连接结束会清理未发布内容。客户端先发送 EOF，再有界结束卡住的进程。
- 写入完成后若版本采样失败，返回完成结果但不提供下一次替换依据，调用方必须重读。已有权限位保留；Windows daemon 使用文件身份与 ChangeTime，并以 ReplaceFileW 保留现有 ACL。
- 两包构建及 macOS daemon 构建通过；10 个共享环境场景分别用于本地与 daemon，另有 9 个 Node、8 个远程回归，涵盖实际版本竞争、同长度修改及恢复 mtime、路径别名切换、分块传输、取消与清理。Durable 离线回归 1039 项通过、3 项条件跳过，env 全包 58 项通过、2 项条件跳过。
- 实际编译产物直接完成本地与 daemon 的创建、替换和过期版本拒绝。工作区依赖及三个浏览器入口检查通过，Windows GNU 目标交叉编译检查通过；Windows 运行尚未验证。
- 完整 Durable 回归还运行了既有真实 Codex 缓存用例，因命中率 0.8991 低于其 0.9 阈值而失败。该用例使用内存存储，不经过本阶段文件实现；离线验证显式排除该单一远程用例，保留其失败记录，不调整阈值。
- 后端条件发布没有宣称能锁住任意外部写入者在最终检查与操作系统发布之间的修改；异常进程或机器退出也可能留下暂存目录。会话观察记录、读写工具接线及持久化恢复仍需下一阶段验证，这一阶段不代表模型已经受文件观察保护。

### Durable 会话文件观察

- `read/edit/write` 使用实际调用会话的一份持久文档，按文件环境身份及规范路径记录观察，每个会话最多保留 1024 个目标。重新打开同一会话保留记录；新分支重新观察，其他文件环境不借用版本依据。被淘汰的目标必须重新读取才能覆盖。
- 已有文件的覆盖与编辑必须先读取。编辑在匹配旧文本前核对版本，在读取编辑底稿后再次核对；成功修改更新观察。持续增长而无法取得稳定版本的日志仍可读取，但不提供覆盖依据；确认缺失与从未观察分别处理。
- 替换依据绑定规范路径和版本，并在异步等待前复制完整依据。实际旧编译产物在目录别名切到另一个硬链接时错误发布了替换；当前本地与 daemon 回归拒绝该调用，保留两个路径的内容，未保留只有版本的旧参数形式。
- diff 和 patch 在文件发布前准备，准备失败不修改文件。已经发布的修改若无法记录观察，结果报告写入完成并提示重读；已取消任务的底层写入随后完成时，真实 SQLite 重开回归验证旧依据仍会被拒绝。
- 13 项会话观察回归通过，包括真实工具任务、分支、SQLite 关闭/恢复、取消后的实际写入、环境隔离、淘汰与故障注入。两包及 coding-agent 构建通过；Durable 离线全包 1056 项、env 全包 60 项、coding-agent 离线全包 3070 项通过，分别有 3、2、50 项条件跳过。既有真实 Codex 缓存用例的失败仍独立记录。
- 编译版默认 TUI 在真实 PTY 和本机 SSE 服务中完成五次请求：盲写被拒绝，随后读取、编辑、再次替换成功，只声明选中的三个工具。正常退出后重开真实会话，观察版本与当前文件一致，工具选择仍为原白名单；夹具服务已关闭。
- 文件错误码传入实际工具结果，错误契约独立为可移植小模块，根入口仍不加载环境实现。Durable 根源码预算为 66/66，三个浏览器入口与 17 项工程回归通过。清理后构建和打包检查包含新的观察模块，未遗留移动前的错误模块产物；Windows 交叉检查通过，Windows 实跑仍未完成。
- SDK 的 AgentSession 文件工具接线继续使用同一份纯观察策略实施；这一阶段没有把 Durable 验收扩大为 Agent 路径已经完成。

### SDK 会话文件观察与统一文件能力

- SDK 的 `read/edit/write` 使用与 Durable 相同的版本、条件发布和有界观察策略。AgentSession 将记录写入实际会话 JSONL，按文件环境与规范路径隔离；重开保留观察，资源重载保留同一所有者，分叉和历史导航必须重新读取。记录不进入模型消息。
