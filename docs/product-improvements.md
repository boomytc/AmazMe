# AmazMe 产品改进与验收

## 目标

在现有 Pi 库、Durable 宿主和 Web/TUI/桌面呈现上吸收 Pi、DeepSeek Harness、QwenPaw、Grok Build 的优秀能力。既有上游记录中的“暂缓”不是产品范围限制。能力必须连接实际执行、持久化、用户交互和失败恢复，不能只增加入口或占位界面。

参考源码位于同级目录 `pi`、`deepseek-harness`、`QwenPaw`。Grok Build 的开源树仅作历史参考，以[官方发布记录](https://x.ai/changelog/build)、[工作流说明](https://x.ai/news/workflows)和[记忆说明](https://x.ai/news/grok-build-memory)确认产品行为，无法确认的内部实现不当成事实。产品保持 `@amazme/*` 包名、中文与英文界面、现有设计令牌和从上到下的依赖方向。不移植整个参照产品，不增加旧 API 转接或双份权威状态。

## 每模块交付规则

1. 重新阅读实现与参照源码，先定义行为、状态归属和用户动作。
2. 修改包后先构建该包，再运行该包测试；不用根目录的全量 build/test 替代验证。
3. 回归必须验证旧行为的实际缺口。真实浏览器、独立安装、子进程与存储恢复使用实际入口。
4. 重读最终文件和 diff，核对要求、生命周期、失败路径、国际化、依赖、重复状态及产物。
5. 自审查有问题就修正；通过后只提交本模块文件，提交说明用中文说明原因。不推送。

## 最终完成条件

所有模块都有当前源码、构建、测试与实际运行证据。UI 必须检查真实呈现及操作，性能必须有测量，外部模型验证和确定性本地协议验证分开报告。清除临时 TODO 卡片、空测试占位与本任务启动的服务，确认 git 工作区状态。证据不足时保持目标进行中，不用“生产就绪”代替缺失的验证。

### SDK 与 print/RPC 工具选择

- `tools` 接受纯名称/模式白名单，或仅含确切 `+name`/`-name` 的增减列表；与默认设置、工具抑制和最后执行的排除规则一致。SDK 与 CLI 使用同一个校验和增减函数，非法列表在加载资源前拒绝。
- 已验证的选择在异步初始化前复制；动态注册的确切工具名保留待激活意图，移除默认激活同样适用于同名扩展。重载接收新增默认工具并继续应用启动实参。
- 实际编译 CLI 通过本机 OpenAI SSE 服务完成请求，模型收到 `read/bash/edit/grep`，未收到被移除的 `write`。非法混用没有创建配置目录或发起模型请求。

- 默认 Durable TUI 的模型、推理、凭据和工具实参仍在后续接线验收中；这一阶段没有把参数解析通过当成 TUI 生效证明。

### 默认 TUI 启动与恢复参数

- 默认交互入口传递模型、推理、临时密钥及启动设置；显式推理优先于模型后缀，新会话读取模型专属和全局默认并按模型能力约束。无效模型在创建或锁定会话存储前拒绝。
- 继续会话先恢复焦点，再应用显式覆盖；其他分支保留原配置。已准备的请求按原模型和推理参数恢复，下一次生成采用新的会话选择。

- 编译版 CLI 在真实 PTY 中访问本机 OpenAI SSE 夹具并显示回复，请求为 `fixture/reason`、`low`，临时密钥正确且未落盘；Ctrl+D 正常退出，立即重新打开已持久会话，设置中的主题仍为原值。
- `@amazme/coding-agent` 构建通过，完整离线测试 3054 项通过、0 项失败、50 项条件跳过；三个浏览器入口及依赖检查通过。本机协议夹具与真实供应商请求分开记录。工具、模型范围和会话选择等其余交互能力继续按索引落实。
