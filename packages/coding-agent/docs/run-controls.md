# 回合审阅与运行控制

默认 TUI、Web 和桌面共享 Durable 的运行钩子。配置仍使用全局设置和受信任项目覆盖，没有独立的第二套权限系统。

## 归档

“归档”统一取消运行任务、后台子任务、排队输入和终端命令，不再提供另一项“停止任务并归档”。归档前确认停止工作；会话历史保留，文件修改不回滚。宿主及工具、模型执行入口拒绝新工作，自动化唤醒也被拒绝，归档会话只能只读查看。旧归档记录同样依据归档状态拒绝执行，不要求另有结束标记。恢复会话会清除归档及兼容的结束标记；已经取消的任务不会自动重放。移除项目也归档并停止其所有会话，被移除的项目随恢复会话一并恢复。

“设置 → 已归档”集中列出归档会话、所属项目和归档时间；打开后只读查看，侧栏只固定当前归档会话，可通过其菜单手动删除。恢复会话回到所属项目，并清空旧的侧栏过滤条件。`archiveRetentionDays` 默认 `0`，长期保留；正数只标记到期会话供手动检查，不自动删除。删除会话不删除项目目录。

## 本轮变更

Web/桌面的“会话工具 → 变更”提供文件列表、增删行数、只读 diff 和已识别的验证命令退出结果。TUI 使用 `/changes` 列文件、`/changes 文件路径` 看差异。没有自动回滚或提交。

以每个对话最近一轮开始前的文件快照为基准，包含 Bash 及其他工具造成的变化，也可能包含人工并发修改，不能全部归因为 Agent。验证命令成功只证明命令退出成功，不代替结果正确性审查。手动刷新空闲会话会比较最新工作区；运行中使用最近完成的工具批次结果。回合中新增工作区从加入时开始比较。

每份快照最多 1500 个文件、单文件 256 KiB、合计 8 MiB，diff 单文件最多 128 KiB；跳过大文件、符号链接、依赖与构建目录，Git 工作区遵循忽略规则。未完整读取的文件不误报为新增或删除。比较文件保存在会话的 `artifacts/review`，原有会话没有追溯快照；新一轮替换审阅入口，供审阅的数据随会话保留。文件内容可能敏感，与原始会话一样需要妥善保管。

## 防止空转与预算

`repeatToolReminder` 默认开启。相同工具与规范化参数连续返回相同结果，在第 3、5、8 次提醒，不强制停止。名称包含独立 `wait`、`poll`、`status` 段的工具排除，结果持续变化的调用也不累计。

`runLimits` 的 `calls`、`seconds`、`cost` 默认均为 `0`，不限。按单个对话每轮计算工具次数、经过秒数、已报告的模型与工具费用（美元）；嵌套工具也计数，子对话独立计费。并行调用逐个预留次数，后续调用因次数不足而暂停时，本次已获准的调用仍可执行；时间、费用限制及恢复时的持久化暂停检查仍然生效。同一任务不重复扣次数。这些预算控制 Agent 的模型请求与工具任务，人工终端面板命令不扣工具次数，仍受归档门禁和文件写入策略约束。到达预算后，在下一次工具或模型执行前暂停，不打断已经开始的命令，因此时间和费用是执行边界预算而非硬实时上限。

Web/桌面设置页可配置，暂停后在“变更”页点击“追加一份预算并继续”。TUI 使用 `/limits 工具次数 秒数 美元`、`/resume_run`。继续重置这份预算，不重放已完成的工具；停止则使用已有的取消流程。暂停标记和已计数任务持久化，重启后仍等待明确继续。尚未启动的工具保存为等待准入，保留已确认参数，恢复后可执行原调用；确认后及准入结束时都只检查原值与当前 schema 是否兼容，不转换类型、补默认值或删除可选空值，不兼容时拒绝执行，需重新发起并确认参数。准入钩子不能改动保存的参数；安全重放被拒绝时取消其子任务，并保留已有输出。预算放行后才保存执行意图，已经记录执行意图的非安全工具仍禁止自动重放。旧版执行记录无法证明未执行，继续保留原有重放限制。

## 文件写入隔离

`executionMode` 默认 `full-access`，沿用本地执行。可选 `read-only` 或 `workspace-write`，后者允许项目所有源目录写入。该字段只读取全局设置，项目文件不能将隔离改为完全访问。TUI `/execution 模式`、Web/桌面设置页控制相同字段。工作区和模式从下一次工具启动生效，已经启动的进程保留当时授权；需要立即撤销时应停止任务。将整个用户目录或运行配置目录授权为工作区，会同时授权控制文件；有隔离需求时不要这样选择。

macOS 使用 `sandbox-exec`，Linux 使用 Bubblewrap。受限 shell 的子进程继承内核文件写入限制；内置文件工具检查规范化路径、符号链接目标及共享 inode。项目写入模式启动 shell 前完整检查工作区，发现任何已有硬链接就拒绝启动，需先替换为独立文件；macOS 禁止 shell 新建硬链接，Linux 的只读外部挂载与独立工作区挂载阻止跨边界建立硬链接。不自动改写或拆除用户文件。后端缺失、探测失败、全局设置损坏或执行模式无效都会明确拒绝执行，不降级为完全访问。终端面板使用同一执行环境。

这只限制文件写入，读取和网络仍开放。AmazMe 主进程、原生插件、独立 MCP 服务不在 shell 沙箱内；原生文件能力的路径检查也不替代针对恶意并发文件系统操作的内核隔离。需要完整隔离时仍应在容器、虚拟机或独立系统账户运行整个宿主。Windows 沿用已有完全访问实现，本次没有实现或实测 Windows 受限后端。

## 摘要前清理

`contextCleanup` 默认开启。除了最近两个工具结果，旧工具文本超过 12000 字符时保留首尾各 3000 字符和原文引用；历史用户、工具图片只向模型发送最近六张。卸载图片的位置会留下明确标记，原始会话不删除文本或图片。

裁剪决定用记录 ID、消息位置和内容指纹区分每次出现，保存在可回溯的会话文档中，在请求、摘要和恢复时使用同一投影。旧版按内容匹配的决定作废，从原始记录重新计算，避免重复图片误卸载。默认可用的只读工具 `context_detail(callId)` 能读取原文，显式工具允许列表仍会限制它。关闭设置停止产生新决定，已经保存的有效决定继续生效，避免恢复时改变输入；新上下文仍由已有摘要机制管理。
