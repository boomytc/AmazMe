# 可选完成验证

通过原生 CLI 的 `-e <本目录>` 或宿主的 `pluginPackages` 选择本插件。未选择时不注册工具或钩子；已选择但未配置时不创建检查任务、策略文档或计时器。Print/RPC 的 SDK 扩展入口不加载此原生 facet。

向模型明确指定检查命令，由 `completion_verification` 的 `configure` 操作保存，例如：

```json
{
  "action": "configure",
  "checks": [{ "name": "构建", "tool": "bash", "command": "npm run build --workspace @example/core" }],
  "maxCorrections": 2,
  "timeoutSeconds": 60
}
```

`status` 查询最近二十轮的候选回答、独立检查结果与修正请求次数；`disable` 关闭后续输入的检查。配置与停用只应按用户指令执行。配置更新在调用所属任务内原子记录，恢复不会把旧配置再次写回；完成检查开始时固定该输入的策略，之后的更改用于下一输入。分支继承分叉时的配置，检查准入与计数从新分支开始。

每次模型给出候选回答后，插件顺序运行所配置的最多八条命令，首次未通过就结束本轮。命令走已有 Bash/PowerShell `ToolTask`，沿用工具选择、参数校验、钩子、审批、环境、输出截断和取消，不直接创建 shell 进程。执行零退出码且无工具错误才记为 `passed`；非零退出码为 `failed`。一次检查轮次共享 1–600 秒的持久截止时间，包含审批和所有命令。失败或超时会反馈给模型，最多再请求 0–8 次修正；没有无限循环。截止时间由检查任务开始时计算，恢复保留原值。

检查期间取消会结束所属命令并等待清理，结果为 `cancelled`。中断命令可能部分执行，恢复遵守原工具的 `unsafe` 策略，记为 `unverified` 并停止自动修正；工具不可用、审批拒绝或缺少可靠退出码也记为 `unverified`。超时后的已中断执行仍保留不确定状态，不因恢复时间较晚而当作新一次确定失败。未开始的过期检查不会继续执行。

模型回答和检查结果分别保存。每轮保存有限的候选摘要（最多 16000 字符，截断有标记），原始完整回答仍在 Harness 检查点与会话记录中。各条检查保存最多 6000 字符的输出、退出码和实际工具任务编号，完整工具结果由已有记录保留。检查任务结束后，普通 `completion_verification status` 工具任务发布该轮回执，Web 与原生界面沿用工具结果呈现；失败达到次数上限时明确标为未验证，不把输入回答完成等同于检查通过。取消时可从 `status` 和任务记录查看结果。

恢复复用原候选回答、检查与回执任务，不重新请求模型或自动重复不安全命令。钩子返回的修正请求服从现有用户跟进和 reset 边界，计数记录已请求次数，不承诺每一请求都实际执行。移除插件后历史记录保留；未结束的插件任务需要重新选择该插件以恢复，或取消。

`src/session.ts` 负责配置工具和完成钩子，`src/check.ts` 负责持久检查任务，`src/state.ts` 定义策略与准入文档。修改源码后，结束或取消当前任务，再通过已有 `/reload` 构建并切换候选。没有第二个 agent loop、执行器或插件注册表。

这项能力只验证显式命令的执行结果；检查命令是否充分覆盖目标，由用户选择。Unix 使用当前实现；PowerShell 复用成熟工具，未实测 Windows。
