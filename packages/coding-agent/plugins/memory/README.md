# 可选项目记忆

插件读取当前项目的 `.amazme/memory.md`，文件可用编辑器、Git 或现有文件工具管理。默认会话不加载此插件，自动捕获也默认关闭。

```bash
amazme -e /path/to/@amazme/coding-agent/plugins/memory
```

同一个目录可用 `amazme install <路径>` 保存选择，也可由宿主加载 session facet。随 npm 包及二进制资源目录交付源码。修改插件后运行 `/reload`，改变选择需重启。

## 读取与修改

`/memory` 请求模型读取项目笔记，`/memory <要求>` 请求管理。也可以直接描述想记住的内容，模型使用 `project_memory`。命令会调用模型；没有新的数据库或专用界面。

- `read` 返回文本、版本与自动捕获状态，并记录现有文件观察。
- `replace` 提交完整 Markdown，必须传入 `read` 返回的 `version`；缺失文件的版本为 `null`。外部修改后重新读取，旧版本不能覆盖新文件。
- `auto_on` / `auto_off` 修改文件首行的 `<!-- auto-capture: true/false -->`。手工编辑同一标记也可控制捕获。关闭后不再产生新捕获；正在提取的任务在保存前再次核对开关。
- `list_candidates` 返回最近 20 个候选的 UUID 与路径，`more` 表示目录还有其他文件。所有候选都是 `.amazme/memory/inbox/*.md`，可直接浏览、编辑或删除。
- `read_candidate` 返回候选文本与版本。`accept` 需传入候选 UUID、`candidateVersion` 和正式记忆的 `version`，两者均须与读取时一致。接受会追加笔记，并保留正式记忆中的其他内容；同一 UUID 不重复追加。

记忆与候选均限制为 32768 字节 UTF-8 文本。读取核对打开文件、规范路径和版本；条件发布使用已有文件修改队列与环境接口。路径越出当前项目、最终符号链接、无效 UTF-8 或读取期间变化均拒绝。正式记忆被外部编辑、清空或删除后，后续请求重新读取，不使用另一份记忆缓存。

文件不可读取时，普通模型请求继续，提示记忆不可用并跳过本次自动捕获；`project_memory` 读取仍返回具体错误，便于通过现有文件工具修复。

## 后台捕获

启用自动捕获后，模型回答提出最终结果时创建 Durable 后台任务，前台不等待提取完成。同一对话的捕获串行执行。任务通过同一 Harness 的自有、无工具对话提取新项目事实与用户明确偏好，30 秒内等待结果；没有新事实时返回 `NONE`。每侧源文字最多 8000 字符，候选正文最多 8000 字符。

任务先保存候选，不自动加入正式记忆或模型上下文。捕获提示排除凭据、临时输出、个人隐私及已有笔记，也不把助手建议当成用户偏好。候选仍需核对；模型提取不等同于事实验证。

任务、来源、请求与阶段保存在原会话存储，关闭后重启可继续。候选采用 UUID 和仅新建发布，恢复不能覆盖被人改过的候选。插件停用时，其未完成任务和所属工作暂停；重新启用可恢复。候选与正式笔记按项目共享，原始会话历史继续保存在原存储中。

正式记忆在每次模型请求中作为过去的项目证据提供，明确当前用户指令优先，笔记不是执行授权。候选不注入上下文。插件关闭后不提供记忆工具、命令或上下文。
