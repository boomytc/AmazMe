# 可选自动化插件

宿主通过已选包的 `server` facet 加载本插件。插件管理计划、时间检查和投递记录，现有 Session worker 和 Harness 执行提示。未选择本插件时不读取计划、不创建定时器，Web 不显示自动化入口。

在宿主的 `pluginPackages` 中选择本目录，或在插件面板添加它并重启宿主。宿主包选择沿用持久 profile；已有会话保持自己的选择。原生 CLI 只加载 `session` 角色，本插件的 `server` 角色由宿主运行。

`src/server.ts` 通过进程内 `HostSessions` 使用宿主目录、逻辑 ID 和会话执行接口；`src/runtime.ts` 管理计划，`src/file.ts` 管理文件租约及提交，`src/records.ts` 校验数据，`src/rules.ts` 计算日历时刻。修改源码后重启宿主，沿原包构建流程加载新的 bundle。没有新增执行器或插件框架。

新建计划时固定 `sessionId` 和 `conversationId`，切换会话焦点不会改变目标。新建操作保持同一计划 ID；编辑核对打开表单时的 `generation`，同一保存重试返回原结果，过期编辑拒绝覆盖。手动运行使用调用者提供的稳定 `requestId`；页面自动重试保持同一编号，同一编号返回原结果，另一个编号在运行期间被拒绝。客户端断开只结束等待，已接纳任务由宿主持有，重连仍可加入同一运行。自动投递按计划 ID、配置版本和实际到期时间编号。运行前提交 `pending`，取得 Harness 的提交编号后记录 `operationId`；连接失败保留原投递并恢复，不用一个新请求替代丢失的回执。

取消、删除和停止会按原投递编号查询、取消和等待实际清理，保留其他排队用户输入。未知编号不会创建输入；已经完成的请求仍记为完成。删除在取消已结算后提交，无法完成取消时保留计划。暂停只停止未来触发，保留原到期时刻；恢复按错过策略处理，暂停期间仍可手动运行。最近二十次结算按请求编号去重并保存在计划中，可在 Web 查看结果、原定时间及开始/结束时间；回答内容由会话历史保存。宿主关闭先停止插件所属请求，再释放 Session handle，避免清理时重开 worker。文件无法写入时仍中止当前实例持有的模型请求，再报告记录待修复，原 pending 留给修复后恢复。

计划保存在 `<agentDir>/schedules.json`，当前为 version 3，根对象包含所属逻辑 `hostId` 和 `schedules`。每个计划要求显式目标、`generation`、`rule`、执行策略、`pending`（无投递时为 null）和 `history`（初始为空数组）。不推断旧文件或不完整记录；旧版本保持原文并进入只读，需明确修复为当前格式再重新读取。格式损坏、无效记录或外部内容变化进入只读状态，不覆盖原文件。

文件租约复用宿主的 `proper-lockfile` 实例，构建时作为 peer 保留，重复加载不再注册独立退出监听。规范路径覆盖目录别名；激活只读，变更或投递才获取租约。另一个进程持有租约时拒绝变更和投递，未取得租约的实例关闭时不取消其他所有者的投递。进程崩溃后租约在十秒过期窗口后可重新取得。丢失租约的实例进入只读并要求重启；普通重新读取不能绕过所有权。临时文件使用 0600 权限，文件和目录同步后才发布状态或投递。文件内容比较检测外部修改；原子性来自参与此协议的宿主租约，不保证任意外部编辑器并发写入。

时间规则与执行策略：

- `interval` 使用正整数 `everyMinutes`，从原定时刻按固定间隔计算，长任务结束后直接到下一个未来时刻。
- `once` 使用不带偏移量的本地 ISO 时间 `at` 和 IANA `timeZone`。运行结算无论完成、拒绝、跳过、取消或超时均消耗这一时刻；结算后禁用且 `nextRunAt` 为 null。显式手动再运行仍可使用新编号。
- `cron` 使用五个数值字段 `expression`（分钟、小时、月中日、月份、星期）及 IANA 时区。支持 `*`、列表、范围和步长；星期日为 0 或 7。月中日和星期都受限时取其并集，否则同时满足。无可用未来时刻的规则拒绝创建。
- 夏令时跳过的本地时刻不平移：一次规则拒绝该时刻，日历规则略过它。重复的本地时刻只使用较早的一次。转换使用 Temporal；其时间歧义说明见 [Temporal 时区指南](https://tc39.es/proposal-temporal/docs/timezone.html)。
- `busy: queue` 使用 Harness 原有 follow-up 队列；`skip` 在忙碌拒绝时记为跳过。`missed: latest` 把错过时刻合并为最近一次；`skip` 超过 `graceMinutes` 则记录跳过，不产生模型输入。宽限为 0–10080 分钟。
- `timeoutSeconds` 为 1–86400 秒，从接纳时计算，包含排队时间；到期取消原请求并等待清理。恢复保留持久截止时间，已过期的 pending 只查询和取消，不重新投递。
- 同一计划不重叠；宿主最多持有四个自动化运行。等待模型不占时间检查和文件队列，其他计划在名额释放后继续。固定目标消失时暂停该计划，保留记录供查看或删除。

Web 新建与编辑只显示当前规则所需字段，运行记录保留最近二十次结果。统一只读诊断与修复指引继续在本插件内实施。
