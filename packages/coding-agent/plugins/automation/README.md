# 可选自动化插件

宿主通过已选包的 `server` facet 加载本插件。插件管理计划、时间检查和投递记录，现有 Session worker 和 Harness 执行提示。未选择本插件时不读取计划、不创建定时器，Web 不显示自动化入口。

在宿主的 `pluginPackages` 中选择本目录，或在插件面板添加它并重启宿主。宿主包选择沿用持久 profile；已有会话保持自己的选择。原生 CLI 只加载 `session` 角色，本插件的 `server` 角色由宿主运行。

`src/server.ts` 通过进程内 `HostSessions` 使用宿主目录、逻辑 ID 和会话执行接口；`src/runtime.ts` 管理计划，`src/file.ts` 管理文件租约及提交，`src/records.ts` 校验数据。修改源码后重启宿主，沿原包构建流程加载新的 bundle。没有新增执行器或插件框架。

新建计划时固定 `sessionId` 和 `conversationId`，切换会话焦点不会改变目标。手动运行使用调用者提供的稳定 `requestId`；页面自动重试保持同一编号，同一编号返回原结果，另一个编号在运行期间被拒绝。客户端断开只结束等待，已接纳任务由宿主持有，重连仍可加入同一运行。自动投递按计划 ID 和到期时间编号。运行前提交 `pending`，取得 Harness 的提交编号后记录 `operationId`；连接失败保留原投递并恢复，不用一个新请求替代丢失的回执。

取消、删除和停止会按原投递编号查询、取消和等待实际清理，保留其他排队用户输入。未知编号不会创建输入；已经完成的请求仍记为完成。删除在取消已结算后提交，无法完成取消时保留计划。暂停只停止未来触发，暂停期间仍可手动运行。最近二十次结算按请求编号去重并保存在计划中，回答内容由会话历史保存。宿主关闭先停止插件所属请求，再释放 Session handle，避免清理时重开 worker。

计划保存在 `<agentDir>/schedules.json`，当前为 version 2，根对象包含所属逻辑 `hostId` 和 `schedules`。每个计划要求显式目标、`pending`（无投递时为 null）和 `history`（初始为空数组）。不推断旧文件的目标或自动运行不完整记录；修复文件中的所属宿主及目标后重新读取。格式损坏、无效记录或外部内容变化进入只读状态，不覆盖原文件。

文件租约复用 `proper-lockfile`，规范路径覆盖目录别名；激活只读，变更或投递才获取租约。另一个进程持有租约时拒绝变更和投递，未取得租约的实例关闭时不取消其他所有者的投递。进程崩溃后租约在十秒过期窗口后可重新取得。丢失租约的实例进入只读并要求重启；普通重新读取不能绕过所有权。临时文件使用 0600 权限，文件和目录同步后才发布状态或投递。文件内容比较检测外部修改；原子性来自参与此协议的宿主租约，不保证任意外部编辑器并发写入。

当前提供按分钟计划、固定目标、稳定投递及恢复、取消和有限结算记录。一次性与日历规则、时区、忙碌与错过执行策略及完整运行记录界面继续在本插件内实施。
