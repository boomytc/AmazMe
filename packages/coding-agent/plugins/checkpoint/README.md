# 可选文件检查点

显式选择后才注册 `file_checkpoint` 与 `/checkpoint`。快照、预览、备份和恢复任务保存在原 Durable 会话存储中，没有另一份 Git 仓库、数据库或后台扫描器。

```bash
amazme -e /path/to/@amazme/coding-agent/plugins/checkpoint
```

目录也可通过 `amazme install <路径>` 保存选择。插件随包和二进制资源目录交付；源码修改后可 `/reload`，改变选择需重启。默认会话不加载检查点插件。

## 使用

`/checkpoint <要求>` 提交普通模型请求。例如保存 `src/app.ts` 和尚不存在的 `src/new.ts`，或预览某个检查点。这会调用模型。

- `create` 必须给出 1–16 个具体文件路径，返回检查点 UUID。保存原始字节，也记录文件不存在的状态；不扫描整个项目。
- `list` 列出当前分支可见的检查点与最近恢复任务编号。
- `preview` 使用检查点 `id`，可指定 `paths` 子集，返回恢复计划 UUID、路径、当前版本、创建/替换/删除动作、前后字节数和有界文本 diff。二进制及超过 32768 字节的文件只列元数据；diff 单文件最多 4000 字符，总计最多 12000 字符，截断时 `patchLimited` 为 true。
- `restore` 必须给出最新预览的 `plan` 和明确的 `paths`，仅选择预览中的文件。先展示计划，按用户的明确选择执行；预览本身不改文件。文件版本或目标变化后，重新预览。
- `status` 返回最近恢复任务状态、结果、冲突与备份 UUID。中途失败或取消后的回滚结果也保存在任务中。
- `remove` 移除当前分支的检查点选择。恢复过程中不能移除记录；保留的历史与其他分支仍由原会话存储管理。

每个文件最多 262144 字节，每份快照最多 1048576 字节，每个分支最多 20 个活动检查点，包含恢复前备份。达到上限时明确要求移除旧记录，不自动删除备份。路径限制在当前项目，拒绝最终符号链接、越界目录别名、重复目标和 `.git` / `.amazme` 内部状态。目录树、文件权限、Git 索引和会话历史不属于文件字节快照。

## 恢复与失败处理

接受预览、保存所选文件的恢复前备份、创建所属恢复任务在同一次 Durable 提交中完成。一个会话存储内只允许一个恢复任务；重试同一工具调用等待原任务，不创建第二份恢复。

恢复和回滚按固定顺序取得所选文件的既有修改队列，条件写入/删除使用原环境后端。编译宿主与源码插件共用进程内的同一队列。其他进程、Bash 或任意外部写入不受该队列锁定，因此每次发布、恢复进度和回滚都核对目标及版本；这是带补偿的逐文件操作，不能把它当作操作系统的跨文件原子事务。

普通失败会按逆序恢复已发布的文件。回滚遇到外部改动时保留新内容，报告 `rollback_conflict` 与备份 UUID，用户可以重新预览备份后决定恢复哪些文件。失败任务和失败工具结果都会明确显示错误，不把回滚当成恢复成功。

插件仍启用时，取消会请求所属任务回滚并等待清理。关闭运行时保留持久进度；重新打开时核对已记下的发布版本和未完成阶段。写入与结果记录之间的中断，以目标字节判断是否已经发布，避免重复写入；不匹配的内容进入回滚/冲突处理。

正在恢复时关闭运行时，随后停用插件再重启，原工具按 Harness 的中断规则失败，其所属任务因定义缺失记录为 `orphaned`，不会偷偷运行插件代码。快照和恢复前备份保留。重新启用后先用 `status` 获取备份 UUID，再预览备份并明确选择要恢复的文件；不要把这种停用解释为一次成功回滚。

检查点随原会话分支的截止点继承，分支后的新检查点不会回到父分支。恢复计划需要在调用分支重新生成；更换项目或执行环境不能使用原计划。检查点恢复只改明确选择的文件，会话继续使用当前历史。
