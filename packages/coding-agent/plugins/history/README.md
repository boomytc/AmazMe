# 可选历史召回

这个 session facet 使用当前会话的 Durable 存储。默认不加载，没有额外数据库、索引或后台任务。

在仓库中可直接选择：

```bash
amazme -e /path/to/AmazMe/packages/coding-agent/plugins/history
```

npm 安装产物也包含 `plugins/history`。使用 `amazme install /path/to/@amazme/coding-agent/plugins/history` 保存选择，或用 `-e` 仅对本次运行启用。宿主可选择同一个包的 session facet。修改插件后运行 `/reload`；删除包选择后重启即可停用。

`/recall <查询>` 提交一次普通模型请求，要求先检索、再读取并引用记录编号。也可直接要求模型查询先前工作。模型调用和结果仍由现有 Harness 执行与保存；此命令会使用模型，没有另建搜索界面。

## 工具

- `history_search`：字面、不区分大小写地检索当前会话分支可见的原始文本。压缩不会删除这些记录。排除当前运行的输入及其后续工具轮次；`before` 是独占的记录编号边界，`nextBefore` 可继续更早的页。每次最多扫描 500 条记录或 100 万字符，返回 1–20 项。单条最多检索前 64000 字符，`textLimited` 表示有未检索的文字；没有结果不能据此断言整个历史不存在相关内容。
- `history_read`：读取一条可见记录的文本窗口。`offset` 按 JavaScript 字符串位置计数，`maxChars` 最多 8000；`nextOffset` 继续长记录。最多访问至约 100 万字符，触达边界时 `textLimited` 为真。

结果包含实际记录编号、原始所属对话和记录类型。继承的祖先记录可以读取，兄弟分支、祖先分叉后的记录和另一会话的数据不能通过编号越界读取。输入、回答、压缩摘要和根或嵌套工具结果的文本可检索；图片只显示类型标记，供应商推理和其他非文本载荷不复制到召回结果。旧的召回工具输出不会再次扩散成新证据。

历史文字是来源证据，当前用户指令仍优先。本文的“原始文本”表示存储记录而非当前压缩摘要的替代内容，不表示导出了完整二进制或任意自定义数据。
